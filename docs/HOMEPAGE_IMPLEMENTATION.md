## 小程序页面

底部导航固定为 **首页 / 商品选购 / 购物车 / 我**。首页按顺序展示：

1. 搜索入口：进入自动聚焦的搜索页，模糊查询商品名称、编码及现有商品搜索字段。
   每次明确提交搜索，为所有匹配的公开商品各累计一次命中；翻页和重试不重复累计。
   热搜榜只使用真实命中数。
2. 店内宣传：图片与短视频混合轮播。视频播放时暂停自动轮播，切页和离开首页时停止播放。
3. 满减优惠券：显示后台配置的有效活动；登录后可领取，重复领取返回同一记录。
4. 品类：复用现有分类及其代表图，点击后进入商品选购并应用分类筛选。
5. 店铺公告：公告图、电话、地址。配置经纬度后可打开微信地图；没有坐标时复制实际地址。
6. 热销商品：从已成交历史订单直接汇总销量、订单数和复购次数；没有成交数据时，明确显示
   “店主推荐”或“新上架好物”，不展示虚构销量。

商品详情新增收藏入口；**我** 中提供我的优惠券、我的收藏、购买记录和连接设置。
我的优惠券只显示本人实际领取记录，保留已过期和已停用的券，未领取的活动不会误标为已领取。
只有后台绑定的店主能看到商家资料入口，编辑名称、电话、地址、坐标和上传公告图。
游客仍可浏览商品和使用本机购物车。

## 浏览器后台怎么配置

登录现有管理员账户，打开 `http://127.0.0.1:8080/admin/shop`，或从商品管理进入首页管理。

- **商家信息**：填写真实店名、电话、地址；可选坐标。店主选择器列出已通过真实微信登录的
  小程序客户，绑定后该客户才获得小程序商家编辑权限。
- **首页资料**：上传轮播图片或MP4、分类代表图和公告图，调整标题、排序及启用状态。
  图片最大5MiB，MP4最大10MiB且不超过60秒；分类和公告只接受静态图片。
- **优惠券**：设置标题、满减金额、开始与结束时间、启用状态。页面以元输入，后端以整数分保存。
- **已成交订单**：录入真实历史成交单号、可选客户、商品、数量和成交单价。服务器保存商品快照并
  计算金额。外部单号唯一，重复的相同记录不会再次计入；作废记录不参与热销和复购统计。

未配置轮播、券或公告时，页面显示相应空状态。开发库不会自动插入虚构活动或订单。

## 后端保持简单

继续使用同一个FastAPI、PostgreSQL和MinIO。迁移 `0006_add_shop_homepage_commerce` 为商品增加
`search_hit_count`，新增七张表：`shop_profiles`、`shop_media`、`shop_coupons`、
`mini_coupon_claims`、`mini_favorites`、`shop_orders`、`shop_order_lines`。
店铺是单条资料；媒体复用已有对象存储和删除重试机制。

销量和复购直接查询订单明细，不新增统计表、统计任务或独立服务。浏览器管理员使用原有Cookie，
小程序私人资料使用独立客户Bearer会话；店主身份只能由管理员绑定。
接口和分页约定见 [首页接口约定](../backend/HOMEPAGE_API.md)。

本阶段实现历史订单记录与展示。购物车结算、微信支付、库存预占和优惠券核销属于后续功能。
匿名历史订单可计销量，只有关联真实小程序客户的订单可计复购并出现在该客户购买记录中。

## 本机查看与运行

在微信开发者工具中导入：

```text
/Users/jennifer.huang/Documents/AI_Workspace/Tools/harbor_market-wechat-miniprogram/miniprogram
```

点击 **编译**。游客首页默认连接 `http://127.0.0.1:8080`。切换地址在 **我 → 连接设置**。
真实微信登录需要匹配的真实AppID和后端AppSecret，配置方法见 [登录集成](WECHAT_LOGIN.md)。
当前本地服务保持微信登录禁用；公开首页可以查看，领取、收藏和店主管理的真实微信联调仍需配置凭证。

此分支的服务使用主项目私有 `.env` 与原有MinIO目录，避免更换媒体存储位置。
数据库升级和新版本镜像准备好后，可从此开发目录重启现有服务：

```bash
MINIO_DATA_DIR=/Users/jennifer.huang/Documents/AI_Workspace/Tools/harbor_market/.data/local-preview/minio \
  docker compose --env-file /Users/jennifer.huang/Documents/AI_Workspace/Tools/harbor_market/.env \
  -f compose.yaml -f compose.development-db.yaml \
  up -d --no-build --no-deps --wait backend cleanup-worker frontend
```

持续开发库只执行备份后的向前迁移。重置数据库、迁移降级及PostgreSQL并发测试必须使用独立测试库。
