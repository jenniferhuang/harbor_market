# 购物车实现

2026-10-11，根据主项目 `docs/04购物车.md` 及购物车、推荐与领券中心原型实现。

## 本阶段功能

- 本机购物车支持逐项勾选、全选/取消全选、反选、编辑数量、移除和清空；旧购物车记录默认勾选，选择状态持久保存。
- 合计、优惠预估和确认选购只使用勾选的商品。同一SKU的多个附加选项仍共同受库存记录限制。
- 购物车显示已领取券的满减门槛、还差金额及优惠预估，可选择一张券或不使用。优惠不叠加，优惠金额最多为已选商品金额，合计不会为负。
- 空购物车提供继续选购与实际公开商品推荐；没有在售商品时不编造推荐、图片或价格。
- 购物车和商品详情均提供领券中心入口。领券中心分页读取当前活动；游客可浏览，领取使用现有微信登录与后台领取接口。只有后台确认的领取结果显示为已领取。
- “去结算”进入确认选购页。登录后，后台按商品编码、SKU、规格和数量重新检查当前公开状态、库存、价格及本账户领券资格。客户端不提交金额；已有价格更新会明确提示。
- 确认页支持重新选择优惠券和不使用优惠券；过期/不再满足门槛的旧选择可取消后重新核对。账号、接口地址、购物车或页面状态改变时，迟到响应不会恢复旧的金额或私人数据。

## 本阶段结算边界

“去结算”完成选购确认和商品优惠后金额核对。当前没有新增订单提交、库存预留、优惠券核销、地址/运费、支付或实际收款功能。确认页明确显示下单暂未开放。金额不含运费，不锁定库存，也不消费优惠券；其后实际下单必须再次校验。

购物车展示的是目录记录与已领券的本地优惠预估。确认页使用后台当前数据，不能将本地预估当作已生成订单金额。

## 后台范围

复用现有商品、SKU、规格、活动券和领取记录，无新表或数据库迁移。

- `GET /api/v1/shop/coupons?page=1&page_size=20`：分页列出当前启用且在有效期内的活动，供领券中心使用。
- `POST /api/v1/mini/shop/cart/quote`：微信客户Bearer认证，读取当前目录与当前客户已领券，返回所选商品的当前金额和券门槛评估。只读操作，不保存购物车或创建订单。

报价输入只接受商品/SKU编码、规格选择、数量和可选券ID。数量与金额有界，按SKU合并库存校验；SKU价格已覆盖的规格不重复加价，纯附加选项才计算价格差。

## 合并与数据

开始本阶段前，`wechat-miniprogram` 的商品选购与共享购物车面板提交 `f1e8af8` 已合入 `main`；后台工作树同步到相同基础。主项目已有需求文档的暂存/未暂存修改保留，合并前补丁位于忽略的 `.data/merge-cart-20261011/`。

本阶段不修改商品、价格、库存或优惠券活动数据。此前鱼类商品仍须补齐真实资料后上架，咖啡归档状态不由本功能改变。不要把持续开发数据库配置为破坏性测试数据库。
